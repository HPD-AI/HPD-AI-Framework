# Consuming Events

Applications consume agent output by registering handlers on the `Agent` instance.

```csharp
agent.On<TextDeltaEvent>(e =>
{
    Console.Write(e.Text);
    return ValueTask.CompletedTask;
});

await agent.RunAsync("Hello!");
```

This replaces the old public `await foreach` pattern. Internally the engine can still use streams, but application code sees a cleaner split:

```text
RunAsync(...) sends input into the agent.
On<TEvent>() handles typed output from the agent.
OnAny() handles all class output events.
```

## Typed Handlers

Use `On<TEvent>()` when the application cares about one event type.

```csharp
agent
    .On<TextDeltaEvent>(e =>
    {
        Console.Write(e.Text);
        return ValueTask.CompletedTask;
    })
    .On<ToolCallStartEvent>(e =>
    {
        Console.WriteLine($"Calling {e.Name}");
        return ValueTask.CompletedTask;
    })
    .On<MessageTurnFinishedEvent>(_ =>
    {
        Console.WriteLine("Done");
        return ValueTask.CompletedTask;
    });
```

Typed handlers use exact runtime type matching in the first implementation.

## Catch-All Handlers

Use `OnAny()` for generic bridges such as WebSocket forwarding, test capture, or debugging.

```csharp
agent.OnAny(async e =>
{
    await websocket.SendAsJsonAsync(e);
});
```

For a single event, handlers run in this order:

```text
1. Matching On<TEvent>() handlers
2. OnAny() handlers
3. Observers
```

## Handler Overloads

The fluent API supports synchronous and asynchronous handlers:

```csharp
agent.On<TextDeltaEvent>(e => Console.Write(e.Text));

agent.On<TextDeltaEvent>(e =>
{
    Console.Write(e.Text);
    return Task.CompletedTask;
});

agent.On<TextDeltaEvent>(e =>
{
    Console.Write(e.Text);
    return ValueTask.CompletedTask;
});
```

All overloads register ordered application handlers and return the same `Agent` instance for chaining.

## Permission Responses

Interactive events are still output events when the agent emits them. Responses are sent back as input events.

```csharp
agent.On<PermissionRequestEvent>(async e =>
{
    var approved = await AskUserAsync(e);

    await agent.RunAsync(new PermissionResponseEvent(
        e.PermissionId,
        e.SourceName,
        approved));
});
```

This replaces direct use of middleware response helpers in normal app code.

## Errors And Completion

Most UIs should track both successful completion and errors:

```csharp
agent
    .On<MessageTurnFinishedEvent>(_ =>
    {
        ui.SetLoading(false);
        return ValueTask.CompletedTask;
    })
    .On<MessageTurnErrorEvent>(e =>
    {
        ui.ShowError(e.ErrorMessage);
        ui.SetLoading(false);
        return ValueTask.CompletedTask;
    });
```

`MessageTurnFinishedEvent` marks the user-visible turn as complete. `AgentTurnFinishedEvent` is lower-level and can fire multiple times inside one user turn.

## Observers

Use observers for telemetry, tracing, metrics, logs, and analytics.

```csharp
var agent = await new AgentBuilder()
    .WithObserver(myObserver)
    .BuildAsync();
```

Observers are background observability hooks. They are not the primary UI or WebSocket event handling API.

## Struct Events

For high-frequency local events such as audio frames, use `OnStruct<TEvent>()` and the struct `RunAsync` overload:

```csharp
agent.OnStruct<AudioInputFrame>(frame =>
{
    audioPipeline.Push(frame);
    return ValueTask.CompletedTask;
});

await agent.RunAsync(new AudioInputFrame(pcm, timestampNs));
```

Struct handlers are agent-owned and do not require application code to start the lower-level `EventCoordinator.RunAsync()` pump.
