# Compaction

Compaction controls how HPD Agent keeps long conversations within a useful model context. When it is enabled, the compaction middleware can compact the model-visible conversation before a turn starts, while optionally preserving, compacting, or deleting the durable branch history.

Use compaction when an agent has long-running sessions, expensive tool loops, or user workflows that should continue for many turns without sending the full transcript to the model every time.

---

## Mental Model

Compaction has four separate decisions:

| Decision | Config property | What it controls |
|----------|-----------------|------------------|
| Is compaction enabled? | `Enabled` | Whether the middleware participates at all. |
| How is history compacted? | `Strategy` | Whether old messages are dropped by count or summarized into replacement context. |
| When does compaction run? | `Trigger` | Count, token, context-window, or composite threshold. |
| What happens to durable branch history? | `Retention` | Preserve full branch history, compact it with replacements, or delete compacted messages. |

The important separation is that `Strategy` affects what the model sees, while `Retention` affects what is kept in the branch. With the default retention policy, compaction is soft: the model sees compacted history, but the branch still keeps the complete durable record.

## Quick Start

### Simple message counting

This keeps the last 20 raw chat messages once the history grows past 25 messages.

```csharp
var agent = new AgentBuilder()
    .WithOpenAI(apiKey, "gpt-4.1")
    .WithCompaction(history =>
    {
        history.Enabled = true;
        history.Strategy = new MessageCountingCompactionOptions
        {
            TargetMessageCount = 20
        };
        history.Trigger = new CountCompactionTriggerOptions
        {
            CountingUnit = HistoryCountingUnit.Messages,
            TargetCount = 20,
            Threshold = 5
        };
    })
    .Build();
```

If `Retention` and `Behavior` are omitted, HPD uses `PreserveBranchHistoryOptions` and `CompactionBehavior.Continue`.

### Summarizing compaction

This summarizes older history and keeps the recent message turns visible to the model.

```csharp
var agent = new AgentBuilder()
    .WithOpenAI(apiKey, "gpt-4.1")
    .WithCompaction(history =>
    {
        history.Enabled = true;
        history.Strategy = new SummarizingCompactionOptions
        {
            TargetRecentMessageCount = 20,
            ResummarizeAfterNewMessages = 5,
            CustomPrompt = "Summarize the conversation, preserving decisions, files, errors, and next steps."
        };
        history.Trigger = new CountCompactionTriggerOptions
        {
            CountingUnit = HistoryCountingUnit.MessageTurns,
            TargetCount = 20,
            Threshold = 5
        };
    })
    .Build();
```

### Use a cheaper summarizer model

The main agent can use one model while summaries are generated by another provider/model.

```csharp
var agent = new AgentBuilder()
    .WithOpenAI(apiKey, "gpt-4.1")
    .WithCompaction(history =>
    {
        history.Enabled = true;
        history.Strategy = new SummarizingCompactionOptions
        {
            TargetRecentMessageCount = 30,
            ResummarizeAfterNewMessages = 5,
            SummarizerProvider = new ProviderConfig
            {
                ProviderKey = "openai",
                ModelName = "gpt-4.1-mini"
            }
        };
        history.Trigger = new CountCompactionTriggerOptions
        {
            CountingUnit = HistoryCountingUnit.MessageTurns,
            TargetCount = 30,
            Threshold = 5
        };
    })
    .Build();
```

### Full configuration

Use `WithCompaction` to configure typed strategies, token triggers, branch retention, or boundary policies.

```csharp
var agent = new AgentBuilder()
    .WithOpenAI(apiKey, "gpt-4.1")
    .WithCompaction(history =>
    {
        history.Enabled = true;

        history.Strategy = new SummarizingCompactionOptions
        {
            TargetRecentMessageCount = 24,
            ResummarizeAfterNewMessages = 6,
            SummaryStyle = SummaryStyle.Handoff,
            UseSingleSummary = true,
            Memory = new SummaryMemoryOptions
            {
                RecentUserMessageTokenBudget = 12_000,
                PreserveRecentUserMessagesSeparately = true,
                ReinjectCurrentContextAfterCompaction = true,
                FilterGeneratedContextWrappers = true
            }
        };

        history.Trigger = new ContextWindowCompactionTriggerOptions
        {
            ContextWindowSize = 128_000,
            TriggerPercentage = 0.80,
            PreservePercentage = 0.30
        };

        history.Retention = new CompactBranchHistoryOptions
        {
            Boundary = new CompositeCompactionBoundaryOptions([
                new IncludeMessageTurnBoundaryOptions(),
                new IncludeToolCallGroupBoundaryOptions()
            ])
        };

        history.Behavior = CompactionBehavior.Continue;
    })
    .Build();
```

## `CompactionConfig`

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `Enabled` | `bool` | `false` | Enables the built-in compaction middleware. If `false`, the rest of the config is ignored. |
| `Strategy` | `CompactionStrategyOptions` | `MessageCountingCompactionOptions` | The reducer used to produce the model-visible history. |
| `Trigger` | `CompactionTriggerOptions` | `CountCompactionTriggerOptions` | The policy that decides whether compaction should run before a turn. |
| `Retention` | `CompactionRetentionOptions` | `PreserveBranchHistoryOptions` | The policy for durable branch history after model-visible compaction. |
| `Behavior` | `CompactionBehavior` | `Continue` | Whether the agent continues after compaction or terminates the current turn as a circuit breaker. |
| `CompactOnFork` | `bool` | `false` | Whether newly forked branches should be compacted before they are persisted. |

## Strategies

Strategies answer: "When compaction happens, what compacted history should the model receive?"

Only one strategy is active. Strategy-specific settings live on that strategy object, so unrelated knobs are not valid for other strategies.

### `MessageCountingCompactionOptions`

Drops older messages from the model-visible history and keeps the most recent messages.

```csharp
history.Strategy = new MessageCountingCompactionOptions
{
    TargetMessageCount = 50
};
```

| Property | Default | Description |
|----------|---------|-------------|
| `TargetMessageCount` | `50` | Number of recent non-system `ChatMessage` objects to keep visible to the model. System messages are handled separately by the middleware and remain at the front of model history. |

Use this for low-cost, predictable compaction when losing older conversational details is acceptable.

### `SummarizingCompactionOptions`

Uses an LLM-backed summarizer to replace older history with a compact summary/memento, then keeps recent messages visible.

```csharp
history.Strategy = new SummarizingCompactionOptions
{
    TargetRecentMessageCount = 30,
    ResummarizeAfterNewMessages = 5,
    CustomPrompt = null,
    SummarizerProvider = new ProviderConfig
    {
        ProviderKey = "openai",
        ModelName = "gpt-4.1-mini"
    },
    UseSingleSummary = true,
    SummaryStyle = SummaryStyle.Handoff,
    Memory = new SummaryMemoryOptions()
};
```

| Property | Default | Description |
|----------|---------|-------------|
| `TargetRecentMessageCount` | `20` | Number of recent non-system messages the summarizing reducer should keep outside the summary. |
| `ResummarizeAfterNewMessages` | `5` | How many new messages can accumulate before the summarizer should refresh a previous summary. |
| `CustomPrompt` | `null` | Optional prompt used by the summarizer instead of HPD's default prompt for the selected `SummaryStyle`. |
| `SummarizerProvider` | `null` | Optional provider/model config for summarization. If omitted, the main agent chat client is used. |
| `UseSingleSummary` | `true` | When using handoff summaries, asks the summarizer to emit one consolidated handoff. If `false`, the prompt asks it to preserve prior summary layers when they matter. |
| `SummaryStyle` | `Handoff` | Controls the default summarization prompt and memento behavior. |
| `Memory` | `new()` | Controls how HPD packages summary replacement messages for continuation. |

Summarizing compaction requires a configured chat client. If no main provider or summarizer provider is available, building the agent fails.

---

## Summary Styles

### `SummaryStyle.Handoff`

`Handoff` is the default. It is designed for continuation: the summary is written as a compact handoff for the next model call, preserving user goals, decisions, rejected paths, files, commands, errors, tests, remaining work, durable facts, and constraints.

When `SummaryStyle.Handoff` is used, HPD also applies `SummaryMemoryOptions` to create structured replacement messages.

### `SummaryStyle.Generic`

`Generic` uses the underlying summarizer behavior without HPD's handoff prompt and memento reshaping. Use this when you want a simpler summary style or when you provide a full `CustomPrompt`.

## Summary Memory Options

`SummaryMemoryOptions` controls the model-visible replacement packet created after summarizing compaction. These options are only used by `SummarizingCompactionOptions` when `SummaryStyle` is `Handoff`.

```csharp
history.Strategy = new SummarizingCompactionOptions
{
    SummaryStyle = SummaryStyle.Handoff,
    Memory = new SummaryMemoryOptions
    {
        RecentUserMessageTokenBudget = 20_000,
        PreserveRecentUserMessagesSeparately = true,
        ReinjectCurrentContextAfterCompaction = true,
        FilterGeneratedContextWrappers = true
    }
};
```

| Property | Default | Description |
|----------|---------|-------------|
| `RecentUserMessageTokenBudget` | `20_000` | Approximate token budget for copying recent compacted user messages into the memento packet. HPD estimates tokens from text length. |
| `PreserveRecentUserMessagesSeparately` | `true` | Copies recent compacted user messages as separate memento messages instead of relying only on the assistant summary. This helps preserve precise user wording and late corrections. |
| `ReinjectCurrentContextAfterCompaction` | `true` | Adds a system boundary message telling the model that earlier conversation was compacted and the following mementos are current context. |
| `FilterGeneratedContextWrappers` | `true` | Removes older HPD-generated memento wrappers before creating the new memento packet, so repeated compactions do not accumulate wrapper noise. |

The generated memento messages are model-visible replacement messages. For soft retention, the original branch history remains durable. For hard compact retention, the same replacement shape can also be inserted into branch history.

## Triggers

Triggers answer: "Should compaction run before this turn?"

Only one trigger object is active unless you use `CompositeCompactionTriggerOptions`.

### `CountCompactionTriggerOptions`

Runs compaction when the configured count exceeds `TargetCount + Threshold`.

```csharp
history.Trigger = new CountCompactionTriggerOptions
{
    CountingUnit = HistoryCountingUnit.MessageTurns,
    TargetCount = 20,
    Threshold = 5
};
```

| Property | Default | Description |
|----------|---------|-------------|
| `CountingUnit` | `MessageTurns` | Whether to count user-visible message turns or raw chat messages. |
| `TargetCount` | `20` | Desired size after compaction for this trigger's count unit. |
| `Threshold` | `5` | Extra count allowed before compaction runs. With `TargetCount = 20` and `Threshold = 5`, compaction runs when the count is greater than 25. |

`TargetCount` belongs to the trigger decision. The actual compacted model history is still controlled by the selected `Strategy`.

### `HistoryCountingUnit.MessageTurns`

Counts completed user-visible message turns. This is usually what product code wants because it does not fluctuate with internal tool call depth.

### `HistoryCountingUnit.Messages`

Counts raw `ChatMessage` protocol objects in the current conversation history. This is more precise, but tool calls, tool results, and protocol-specific messages can make the count grow faster than visible user turns.

### `TokenBudgetCompactionTriggerOptions`

Runs compaction based on the last observed model input token count.

```csharp
history.Trigger = new TokenBudgetCompactionTriggerOptions
{
    TargetTokenBudget = 100_000,
    TokenBudgetThreshold = 10_000
};
```

| Property | Default | Description |
|----------|---------|-------------|
| `TargetTokenBudget` | `0` | Desired input token budget. Must be greater than zero when this trigger is used. |
| `TokenBudgetThreshold` | `0` | Extra tokens allowed before compaction runs. With `TargetTokenBudget = 100_000` and `TokenBudgetThreshold = 10_000`, compaction runs after a prior turn reports more than 110,000 input tokens. |

Token triggers use usage reported by the previous model turn. On the first turn, there may be no observed token usage yet, so this trigger will not fire unless compaction is forced with `AgentRunConfig.TriggerCompaction`.

### `ContextWindowCompactionTriggerOptions`

Runs compaction when the last observed input token count exceeds a percentage of the model context window.

```csharp
history.Trigger = new ContextWindowCompactionTriggerOptions
{
    ContextWindowSize = 128_000,
    TriggerPercentage = 0.80,
    PreservePercentage = 0.30
};
```

| Property | Default | Description |
|----------|---------|-------------|
| `ContextWindowSize` | `0` | Model context window size in tokens. Must be between 1,000 and 2,000,000 when used. |
| `TriggerPercentage` | `0` | Fraction of the context window that triggers compaction. `0.80` on a 128,000-token model triggers after more than 102,400 observed input tokens. |
| `PreservePercentage` | `0.30` | Desired preserved portion of the context window. Built-in reducers still use the selected strategy's count settings for actual retention; this value documents the token-budget intent for context-window policies. |

Like token-budget triggers, context-window triggers depend on token usage from a previous turn.

### `CompositeCompactionTriggerOptions`

Runs compaction when any child trigger fires.

```csharp
history.Trigger = new CompositeCompactionTriggerOptions
{
    AnyOf =
    [
        new CountCompactionTriggerOptions
        {
            CountingUnit = HistoryCountingUnit.MessageTurns,
            TargetCount = 30,
            Threshold = 5
        },
        new ContextWindowCompactionTriggerOptions
        {
            ContextWindowSize = 128_000,
            TriggerPercentage = 0.80,
            PreservePercentage = 0.30
        }
    ]
};
```

| Property | Description |
|----------|-------------|
| `AnyOf` | Child triggers. Compaction runs as soon as one child trigger says it should run. |

## Retention Policies

Retention answers: "After model-visible history is compacted, what should happen to durable branch history?"

### `PreserveBranchHistoryOptions`

Soft compaction. The model receives compacted history, but branch history remains complete.

```csharp
history.Retention = new PreserveBranchHistoryOptions();
```

Use this when you want safe compaction with full auditability, replay, branching, or later inspection.

### `CompactBranchHistoryOptions`

Hard compaction. HPD removes compacted messages from durable branch history and inserts replacement messages, such as the summary/memento generated by summarizing compaction.

```csharp
history.Retention = new CompactBranchHistoryOptions
{
    Boundary = new IncludeMessageTurnBoundaryOptions()
};
```

Use this when durable branch storage should shrink but future projection should still retain compact context.

### `DeleteCompactedMessagesOptions`

Hard deletion. HPD removes compacted messages from durable branch history and does not insert replacements.

```csharp
history.Retention = new DeleteCompactedMessagesOptions
{
    Boundary = new ExactCompactedMessagesBoundaryOptions()
};
```

Use this only when older durable messages can be discarded without a compact substitute.

## Compaction Boundaries

Boundaries apply only to hard retention policies: `CompactBranchHistoryOptions` and `DeleteCompactedMessagesOptions`.

They answer: "If the reducer marks these messages as compacted, should durable branch compaction expand to include nearby related messages?"

### `ExactCompactedMessagesBoundaryOptions`

Removes exactly the messages compacted from model-visible history, excluding messages the strategy retained and system messages.

```csharp
Boundary = new ExactCompactedMessagesBoundaryOptions()
```

### `IncludePreviousMessagesBoundaryOptions`

Also removes a fixed number of previous durable messages before each compacted message.

```csharp
Boundary = new IncludePreviousMessagesBoundaryOptions(2)
```

This is useful when a compaction point lands after context-setting messages that should be compacted together.

### `IncludeMessageTurnBoundaryOptions`

Expands compaction to messages from the same HPD message turn.

```csharp
Boundary = new IncludeMessageTurnBoundaryOptions()
```

Use this when internal tool calls, reasoning, or assistant messages belong to one user-visible turn and should not be split across durable history.

### `IncludeToolCallGroupBoundaryOptions`

Expands compaction across tool call/result groups that share the same tool call ID.

```csharp
Boundary = new IncludeToolCallGroupBoundaryOptions()
```

Use this when deleting a tool call without its result, or a result without its call, would make branch history confusing.

### `CompositeCompactionBoundaryOptions`

Applies multiple boundary policies.

```csharp
Boundary = new CompositeCompactionBoundaryOptions([
    new IncludeMessageTurnBoundaryOptions(),
    new IncludeToolCallGroupBoundaryOptions()
])
```

## Behavior

`CompactionBehavior` controls what happens after compaction is performed.

| Value | Description |
|-------|-------------|
| `Continue` | Default. Compaction happens before the turn and the agent continues immediately. |
| `CircuitBreaker` | Compaction terminates the current turn. The user or application must send another turn to continue. |

```csharp
history.Behavior = CompactionBehavior.CircuitBreaker;
```

Circuit breaker mode is useful when users need to know that context was compressed before the agent continues.

## Fork Compaction

`CompactOnFork` controls whether a newly forked branch is born compacted.

```csharp
var agent = new AgentBuilder()
    .WithOpenAI(apiKey, "gpt-4.1")
    .WithCompaction(history =>
    {
        history.Enabled = true;
        history.CompactOnFork = true;
        history.Strategy = new SummarizingCompactionOptions
        {
            TargetRecentMessageCount = 24,
            SummaryStyle = SummaryStyle.Handoff
        };
    })
    .Build();
```

When this is enabled, the fork target is compacted during branch creation, before the
new branch is saved. The source branch is not changed.

Fork compaction is useful for:

- edit or retry branches that should start with less copied history;
- manually-created branches that do not need the full raw parent transcript;
- SubAgent branches that need parent context, but not every old message.

By default, `CompactOnFork` applies to all branch forks created by the agent. SubAgents
can override that per execution policy:

```csharp
SubAgentExecutionPolicies.ParentSessionForkedBranch(
    branchCompaction: SubAgentBranchCompaction.Enabled)
```

or:

```csharp
SubAgentExecutionPolicies.ParentSessionForkedBranch(
    branchCompaction: SubAgentBranchCompaction.Disabled)
```

`Enabled` compacts that SubAgent's fork even when global `CompactOnFork` is `false`.
`Disabled` skips compaction for that SubAgent's fork even when global `CompactOnFork`
is `true`. The default is `Inherit`, which uses `CompactOnFork`.

These SubAgent options select fork-time behavior only. The compaction strategy,
summary style, retention policy, and boundaries still come from this agent's
`WithCompaction(...)` configuration.

Fork compaction only applies to branches that are actually forked from existing
history. It does not apply to fresh branches, existing branches, or SubAgents that write
directly into the parent branch.

## Per-Run Overrides

`AgentRunConfig` can force, skip, or change compaction behavior for one run.

```csharp
await agent.RunAsync("Before the next phase, compact context.", new AgentRunConfig
{
    TriggerCompaction = true
});
```

```csharp
await agent.RunAsync("Use the full context for this decision.", new AgentRunConfig
{
    SkipCompaction = true
});
```

```csharp
await agent.RunAsync("Continue after compacting unless this run says otherwise.", new AgentRunConfig
{
    CompactionBehaviorOverride = CompactionBehavior.CircuitBreaker
});
```

| Property | Description |
|----------|-------------|
| `TriggerCompaction` | Forces compaction before this turn, regardless of automatic trigger thresholds. |
| `SkipCompaction` | Skips compaction for this turn, even if automatic thresholds would fire. Takes precedence over `TriggerCompaction`. |
| `CompactionBehaviorOverride` | Overrides `CompactionConfig.Behavior` for this turn only. |

## Events

Compaction emits a `CompactionEvent` when it is skipped or performed. The event status enum also includes `CacheHit` for compatibility with older compaction-state reporting.

Important fields:

| Field | Description |
|-------|-------------|
| `Status` | `Skipped`, `Performed`, or `CacheHit`. |
| `Strategy` | The active strategy kind: `MessageCounting` or `Summarizing`. |
| `OriginalMessageCount` | Number of non-system messages considered before compaction. |
| `CompactedMessageCount` | Number of model-visible messages after compaction. |
| `MessagesRemoved` | Number of original messages removed from model-visible history. |
| `SummaryContent` | Summary text when summarizing compaction produced one. |
| `Reason` | Human-readable reason, such as count threshold, token threshold, explicit trigger, or skip reason. |

When hard branch retention compacts durable history, HPD also records a branch history compaction event in the branch event stream.

## JSON Configuration

Compaction options are polymorphic and use `$type` discriminators.

```json
{
  "Compaction": {
    "Enabled": true,
    "Strategy": {
      "$type": "summarizing",
      "TargetRecentMessageCount": 24,
      "ResummarizeAfterNewMessages": 6,
      "UseSingleSummary": true,
      "SummaryStyle": "Handoff",
      "Memory": {
        "RecentUserMessageTokenBudget": 12000,
        "PreserveRecentUserMessagesSeparately": true,
        "ReinjectCurrentContextAfterCompaction": true,
        "FilterGeneratedContextWrappers": true
      }
    },
    "Trigger": {
      "$type": "contextWindow",
      "ContextWindowSize": 128000,
      "TriggerPercentage": 0.8,
      "PreservePercentage": 0.3
    },
    "Retention": {
      "$type": "compact",
      "Boundary": {
        "$type": "composite",
        "Policies": [
          { "$type": "includeMessageTurn" },
          { "$type": "includeToolCallGroup" }
        ]
      }
    },
    "Behavior": "Continue"
  }
}
```

Supported discriminator values:

| Base type | `$type` values |
|-----------|----------------|
| `CompactionStrategyOptions` | `messageCounting`, `summarizing` |
| `CompactionTriggerOptions` | `count`, `tokenBudget`, `contextWindow`, `composite` |
| `CompactionRetentionOptions` | `preserve`, `compact`, `delete` |
| `CompactionBoundaryOptions` | `exactCompactedMessages`, `includePreviousMessages`, `includeMessageTurn`, `includeToolCallGroup`, `composite` |

## Choosing a Configuration

Use message counting when:

- cost matters more than preserving older detail;
- the agent handles short tasks with occasional long chats;
- deterministic behavior is more important than rich continuity.

Use summarizing compaction when:

- the user may work across many turns;
- older decisions, files, tool results, or constraints need to survive;
- you can afford an extra summarization model call.

Use token or context-window triggers when:

- the provider reports usage details;
- conversation length is unpredictable;
- you want compaction to follow actual context pressure instead of turn count.

Use hard compact retention when:

- branch storage must shrink;
- future branch projection should include compact replacement context;
- you can accept losing the exact compacted durable messages.

Use preserve retention when:

- auditability matters;
- branch replay or inspection matters;
- you want the safest default.

## Validation Rules

HPD validates enabled compaction configs during agent construction.

| Option | Rule |
|--------|------|
| `MessageCountingCompactionOptions.TargetMessageCount` | Between 2 and 1,000. |
| `SummarizingCompactionOptions.TargetRecentMessageCount` | Between 2 and 1,000. |
| `SummarizingCompactionOptions.ResummarizeAfterNewMessages` | Between 0 and 100. |
| `SummaryMemoryOptions.RecentUserMessageTokenBudget` | Zero or greater. |
| `CountCompactionTriggerOptions.TargetCount` | Between 2 and 1,000. |
| `CountCompactionTriggerOptions.Threshold` | Between 0 and 100. |
| `TokenBudgetCompactionTriggerOptions.TargetTokenBudget` | Greater than zero. |
| `TokenBudgetCompactionTriggerOptions.TokenBudgetThreshold` | Zero or greater. |
| `ContextWindowCompactionTriggerOptions.ContextWindowSize` | Between 1,000 and 2,000,000. |
| `ContextWindowCompactionTriggerOptions.TriggerPercentage` | Greater than 0 and less than 1. |
| `ContextWindowCompactionTriggerOptions.PreservePercentage` | Greater than 0 and less than 1. |
| `ContextWindowCompactionTriggerOptions.TriggerPercentage` | Must be larger than `PreservePercentage`. |
| `CompositeCompactionTriggerOptions.AnyOf` | Must include at least one trigger. |
| `IncludePreviousMessagesBoundaryOptions.Count` | Zero or greater. |
| `CompositeCompactionBoundaryOptions.Policies` | Must include at least one boundary policy. |
