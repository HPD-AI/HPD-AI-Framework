# Events Overview

HPD-Agent is event-driven in both directions:

```text
Into the agent:  RunAsync(inputEvent)
Out of the agent: On<TEvent>() / OnAny()
```

The agent still streams text, tool progress, permission requests, turn lifecycle events, and errors in real time. The public API no longer exposes those outputs as an `await foreach` stream. Applications register handlers and then send input events.

## Basic Shape

```csharp
var agent = await new AgentBuilder()
    .WithProvider("openai", "gpt-4o")
    .WithInstructions("You are helpful.")
    .BuildAsync();

agent
    .On<TextDeltaEvent>(e =>
    {
        Console.Write(e.Text);
        return ValueTask.CompletedTask;
    })
    .On<MessageTurnFinishedEvent>(_ =>
    {
        Console.WriteLine("\nDone");
        return ValueTask.CompletedTask;
    });

await agent.RunAsync("Hello!");
```

For event-native input:

```csharp
await agent.RunAsync(new UserTextInputEvent("Hello!")
{
    SessionId = "user-123",
    BranchId = "main"
});
```

## Event Channels

Events carry both a `Kind` and a `Channel`.

| Concept | Purpose |
|---|---|
| `EventKind` | Classifies the event for filtering and diagnostics. |
| `EventChannel` | Controls routing, backpressure, and transport behavior. |

Common channel usage:

| Channel | Typical events |
|---|---|
| `Streaming` | Text, reasoning, audio, and high-throughput deltas |
| `Synchronous` | Message lifecycle, agent turn lifecycle, tool lifecycle |
| `Interactive` | User input, permission, clarification, client tool requests/responses |
| `Control` | Interruption, cancellation, circuit breaker, stop signals |

## Input Events

The primary text input event is `UserTextInputEvent`:

```csharp
await agent.RunAsync(new UserTextInputEvent("Summarize this")
{
    SessionId = "session-123",
    BranchId = "main",
    RunConfig = new AgentRunConfig
    {
        CoalesceDeltas = false
    }
});
```

The string overload is convenience syntax:

```csharp
await agent.RunAsync(
    "Summarize this",
    sessionId: "session-123",
    branchId: "main");
```

Response and control events also enter through `RunAsync(...)`:

```csharp
await agent.RunAsync(new PermissionResponseEvent(
    permissionId,
    sourceName,
    approved));

await agent.RunAsync(new InterruptionRequestEvent(
    StreamId: null,
    Reason: "User clicked stop",
    Source: InterruptionSource.User));
```

## Output Handlers

Typed handlers run before catch-all handlers. Observers run after ordered app handlers.

```text
1. Exact On<TEvent>() handlers, in registration order
2. OnAny() handlers, in registration order
3. IAgentEventObserver dispatch
```

```csharp
agent.On<ToolCallStartEvent>(e =>
{
    Console.WriteLine($"Calling {e.Name}");
    return ValueTask.CompletedTask;
});

agent.OnAny(e =>
{
    logger.LogDebug("Agent event: {Type}", e.GetType().Name);
    return ValueTask.CompletedTask;
});
```

`On<TEvent>()` is output-only. Even if `TEvent` is an input event type, input still enters the agent through `RunAsync(...)`.

## Realtime Runtime

For long-lived apps, start the runtime once and send input events over time:

```csharp
await agent.StartAsync();

await agent.RunAsync(new UserTextInputEvent("hello")
{
    SessionId = "user-123",
    BranchId = "main"
});

await agent.RunAsync(new InterruptionRequestEvent(
    StreamId: null,
    Reason: "User clicked stop",
    Source: InterruptionSource.User));

await agent.StopAsync();
```

When the runtime is not started, `RunAsync(UserTextInputEvent)` returns when the turn completes. When the runtime is started, `RunAsync(input)` returns when the input event is accepted or delivered to the relevant response/control path.
